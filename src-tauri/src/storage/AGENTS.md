# Storage

Area instructions for `src-tauri/src/storage/` and `src-tauri/migrations/`. The root `AGENTS.md` (project-wide rules) applies too.

- `src-tauri/src/storage/`: rusqlite settings/archive/personalization (`personalization/{topics,ranking}.rs`)/AI inventory/classification/proactive/Cybercampus APIs, FTS and upgrade tests; ordered migrations are in `src-tauri/migrations/`. Modules: `archive.rs` (documents, revisions, resources, FTS search, skipped notices), `intelligence.rs` (model inventory, vectors, classifications, feed AI joins), `cybercampus.rs`, `proactive.rs`, `notification_activation.rs` (`cfg(any(windows, test))`), `personalization.rs`; tests in `*_tests.rs` beside them (`archive_tests`, `feed_tests`, `intelligence_tests`, `personalization_tests`, `proactive_tests`) and `calendar/reminder_tests.rs`. `storage/feed.rs` applies decoded feed files (`feed_apply_snapshot`/`feed_apply_segment`, #177); `storage/feed/state.rs` holds the sync state (base, accepted `generated_at` and the previous one, board health, last result) and `feed_status`. `storage/notice_dates.rs` stores the dates `crates/sources/src/dates.rs` finds in each notice's current title and body (see the calendar dates invariant in the root `AGENTS.md`). `storage/trash.rs` owns 휴지통 and permanent deletion (see the data invariants). `storage/calendar.rs` holds the user's todos (local wall-clock `day`/`time`, never sent anywhere or used for ranking/notice notifications); `src-tauri/src/calendar_export.rs` (command `calendar_export`, #191) writes todos not done plus open eClass deadlines to an `.ics` file only at the path the user picks, never notice dates. A todo can be prefilled from a date found in a notice or an open eClass deadline (`noticeDateTodo`/`taskTodo` in `lib/archive-format.ts`), always through the editable form and an explicit save; extraction never creates a todo by itself. A todo made from a notice keeps `document_id`: a new revision leaves the todo unchanged, 휴지통 hides the link until the notice is restored, and permanent deletion clears it (trigger in migration 031); eClass todos keep no link. `storage/studium.rs` persists selected rooms, the display room, automatic interval, per-room favorites and native mini-window geometry only; no automatic enablement, seat results, responses or history are durable. `storage/studium_alerts.rs` holds only room rules/rearm latches, hashed activation capabilities and bounded delivery-attempt accounting. Every query that shows a board selects its name through the `source_label!()` SQL macro (`storage/mod.rs`): `<unit> · <board>`, the unit from the organization after `서강대학교 · ` (user decision, #80 step 3).

## Schema and data invariants

- Each migration's contents are in the `docs/ARCHITECTURE.md` "Storage and schemas" table; update that table with every new migration and never rewrite a released one. Rust tests get a throwaway store from `storage::temp_store()` (`cfg(test)`, `storage/mod.rs`); schema-rollback tests build their scripts from the layered `#[cfg(test)]` `UNDO_*` fragments there, so a new migration adds one fragment. Upgrade tests that roll a profile back to an older schema must drop every later table and column (below 14, restore the columns and `ai_jobs` 033 removed through `RETIRED_GENERATION` in `storage/archive_tests.rs`), including `calendar_events`, `feed_state.events_known` and `settings.calendar_academic` (below 43), `notice_dates`, `notice_date_extractions` and `settings.calendar_all_deadlines` (below 32), `calendar_todos` (drop the `calendar_todos_document_deleted` trigger first; below 31 also its index and `document_id`), `studium_mini_geometry`, `studium_alert_tokens`, `studium_alert_attempts`, `studium_alert_rules`, `studium_favorite_seats`, `studium_preferences` and `studium_selected_rooms` (the view preference references the selected rooms, so drop it first), `settings.clock_format`, `trashed_documents`, `deleted_notices`, `settings.auto_trash_months` and `studium_preferences.interval_minutes`. AI, personalization and proactive state remain separate from authoritative archive content except explicit identity references. Require populated-old-schema upgrade, transactional rollback and newer-schema rejection tests; do not change a newer DB even to enable WAL.
- **휴지통 (user decision):** the behavior is in `docs/ARCHITECTURE.md` "휴지통" (under "Storage and schemas"). Moving to 휴지통 must keep every byte, revision, user state and classification. Any new query over `documents` must apply `trash::NOT_TRASHED`. Never empty 휴지통 automatically or make the old-notice cleanup delete anything; permanent deletion happens only from 휴지통, records a tombstone, and removes unreferenced files only after the store lock is released.
