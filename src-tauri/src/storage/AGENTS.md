# Storage

Area instructions for `src-tauri/src/storage/` and `src-tauri/migrations/`. The root `AGENTS.md` (project-wide rules) applies too.

- `src-tauri/src/storage/`: rusqlite settings/archive/personalization (`personalization/{topics,ranking}.rs`)/AI inventory/classification/proactive/Cybercampus APIs, FTS and upgrade tests; ordered migrations through `042_feed_known_boards.sql` are in `src-tauri/migrations/`. `storage/feed.rs` applies decoded feed files (`feed_apply_snapshot`/`feed_apply_segment`, #177); `storage/feed/state.rs` holds the sync state (base, accepted `generated_at` and the previous one, board health, last result) and `feed_status`. `storage/notice_dates.rs` stores the dates `crates/sources/src/dates.rs` finds in each notice's current title and body (see the calendar dates invariant in the root `AGENTS.md`). `storage/trash.rs` owns 휴지통 and permanent deletion (see the data invariants). `storage/calendar.rs` holds the user's todos (local wall-clock `day`/`time`, never sent anywhere or used for ranking/notice notifications); `calendar_export.rs` (`calendar_export`, #191) writes todos not done plus open eClass deadlines to an `.ics` file only at the path the user picks, never notice dates. A todo can be prefilled from a date found in a notice or an open eClass deadline (`noticeDateTodo`/`taskTodo` in `lib/archive-format.ts`), always through the editable form and an explicit save; extraction never creates a todo by itself. A todo made from a notice keeps `document_id`: a new revision leaves the todo unchanged, 휴지통 hides the link until the notice is restored, and permanent deletion clears it (trigger in migration 031); eClass todos keep no link. `storage/studium.rs` persists selected rooms, the display room, automatic interval, per-room favorites and native mini-window geometry only; no automatic enablement, seat results, responses or history are durable. `storage/studium_alerts.rs` holds only room rules/rearm latches, hashed activation capabilities and bounded delivery-attempt accounting. Every query that shows a board selects its name through the `source_label!()` SQL macro (`storage/mod.rs`): `<unit> · <board>`, the unit from the organization after `서강대학교 · ` (user decision, #80 step 3).

AI, personalization and proactive state remain separate from authoritative archive content except explicit identity references. Require populated-old-schema upgrade, transactional rollback and newer-schema rejection tests; do not change a newer DB even to enable WAL.
- **휴지통 (user decision):** moving a notice to 휴지통 (`trashed_documents`) keeps every byte, revision, user state and classification; `trash::NOT_TRASHED` must exclude it from lists, search, categories, counts, recommendations, learned-topic evidence, classification candidates and similar/duplicate notices, and proactive treats it as an inactive source (never notified or replayed on restore). Sync still revises a trashed notice. Nothing empties 휴지통 automatically. The opt-in old-notice period (`settings.auto_trash_months`, default 0 = never; `Store::auto_trash_old`) only moves unsaved notices with a dated `published_at` older than the cutoff into 휴지통; it never deletes, and a restored notice still older than the cutoff moves back on the next run. Permanent deletion is only from 휴지통, deletes the document (cascade), clears its skipped row, records a `deleted_notices` tombstone and returns content-addressed files that no remaining resource uses, which the command removes after the store lock is released. A tombstoned `(source_id, external_id)` is never fetched again: Cybercampus skips it (a fetch counts as an eClass view) and `upsert_article` rejects it. Any new query over `documents` must apply `NOT_TRASHED`.
