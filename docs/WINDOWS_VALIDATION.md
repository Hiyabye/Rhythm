Restore is restricted to a local fixed NTFS app-data directory; backup input can be selected separately. The Cloud Files API check rejects registered sync roots and fails closed when their status cannot be confirmed; it cannot detect every third-party sync tool, so users must not manually synchronize the app-data directory. Product builds use LocalAppData without a user-selectable restore destination. The Cloud Files check still needs integration validation with a registered test sync root; no user sync data was modified for this work. The implementation preserves previous data and stops on ambiguous recovery artifacts. Neither a successful function call nor the test plan above establishes a guarantee against all power failures or hardware faults.
