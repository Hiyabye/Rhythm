# Roadmap

Rhythm stays local-first and Korean-first. The current release is **v1.10.0**. Support targets macOS Apple Silicon and Windows 11 x64; Linux and Intel Macs are not supported. Planned work is tracked in [GitHub issues](https://github.com/Hiyabye/Rhythm/issues); this page records the current state and what has actually been verified.

## Current state

- **Archive:** 35 sources, all supported: 34 public Sogang boards (main academic, computing, engineering, 전자공학과/시스템반도체공학과 community boards, 벨라르미노 학사 dormitory boards, 기계공학과 sitemap-backed boards, 반도체공학과 boards) and the opt-in Cybercampus (eClass) connector for the current term's course notices, assignments and TODO deadlines. **새로고침** merges the new-notice check and the earlier-notice import; notices whose body cannot be archived are skipped and listed per board.
- **Studium:** a separate opt-in extension for manual or explicitly started app-open automatic checks of one to seven library reading rooms. Automatic mode is session-only and off at launch; its saved interval defaults to 5 minutes (integers 2–60). Selected rooms, the displayed room, room-specific favorites, default-off alert conditions and native mini-window geometry persist (schema 30). Exact-number search, favorite highlights and the optional relative seat map use the same validated response locally; map errors preserve verified numbers/counts. Fresh manual/automatic results may trigger opted-in seat alerts under the existing notification permission, quiet-hours and shared rate policy. The explicitly opened mini window and existing-tray summary share the same in-memory results; closing mini preserves any running check, and neither open state nor always-on-top survives a new window/session. Failed rooms lose their previous values; neither observed coordinates nor seat history are stored. Enabling, navigation, map operations and settings changes start no school requests or alerts. No reservations.
- **Local AI:** upstream `llama-server` (llama.cpp b12068, bundled and supervised by Rhythm) on both platforms. Catalog: Qwen3.5 2B/4B and Gemma 4 E2B/E4B plus an optional vision projector per model, and Qwen3-Embedding 0.6B for classification, similar notices and semantic search. Opt-in idle backlog analysis (up to 20 notices per hour).
- **Remote AI:** opt-in OpenAI-compatible engine; the local engine stays the default.
- **Personalization, lifecycle and notifications:** deterministic ranking, opt-in background sync and notifications, backup and restore (schema 30).
- **Calendar:** opt-in month view of open eClass deadlines, AI reference dates and local todos (never sent anywhere, no reminders); unfinished todos also show in 앞으로 7일.
- **First-run setup:** a new profile opens a guided setup (theme, boards, interests, AI, background, notifications) before the app; it can be rerun from Settings and resets nothing.
- **Windows 11 x64:** per-user unsigned NSIS installer, CPU and NVIDIA Vulkan AI, WinRT notifications. See [Windows](WINDOWS.md).
- **Distribution:** ad-hoc-signed macOS DMG and unsigned Windows installer, with signed in-app updates and a daily automatic update check (announce-only), built by the tag-triggered `release.yml` into a draft release.

## Open decisions

Each is a GitHub issue:

- **Cloud summaries for public notices** (#39 and follow-ups): precompute notice summaries on a backend and keep the local model for personal data. Not decided. The shipped opt-in user-configured remote engine (#77) is a separate client and does not authorize a Rhythm-operated backend.
- **Build and CI speed** (#9–#14, #17, #20, #23).

## Possible extensions

Each is a future product decision, sharing the archive, search and personalization core:

- **Opportunities:** competitions, activities, internships, research and jobs.
- **Email:** after OAuth and provider limits are handled deliberately.
- **Personal agent:** proposals and workflows whose consequential actions stay under user control.

Platform work, also future decisions: Linux (re-review the `glib 0.18.5` / RUSTSEC-2024-0429 finding first), Intel Macs, Developer ID signing and notarization. Windows builds stay unsigned by user decision (#85); SmartScreen warnings remain expected.
