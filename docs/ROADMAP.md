# Roadmap

Rhythm stays local-first for personal data and Korean-first. The current release is **v2.4.1**. Support targets macOS Apple Silicon and Windows 11 x64; Linux, Intel Macs and ARM Windows are not supported. Planned work is tracked in [GitHub issues](https://github.com/Hiyabye/Rhythm/issues); this page records the current state and what has actually been verified.

## Current state

- **Collector and feed (#166):** `rhythm-collector` runs about once an hour in `rhythm-fetch/collector` (scheduled every 30 minutes; GitHub fires about one scheduled run an hour, #218) (GitHub Actions, pinned to one Rhythm `main` commit), crawls the 172 public boards of that commit's catalog (main site, computing, engineering, community, k2web, mechanical, semiconductor, WordPress, vendor and admission families; list in `crates/sources/AGENTS.md`), embeds and classifies them through Workers AI, keeps its state in private R2 and publishes the signed feed ([FEED.md](FEED.md)) through the read-only `rhythm-feed` Worker. Production has run since 2026-11-18.
- **Archive:** 173 sources, all supported. The 172 public boards (128 k2web boards added in #80 step 3) arrive only through the feed (title, metadata, a 320-character excerpt, dates, links, vectors, categories); opening a notice fetches its body and files from the school. The opt-in Cybercampus (eClass) connector is the only source the app collects itself: the current term's course notices, assignments and TODO deadlines. A v1 profile is upgraded in place (migrations 037–042): its notices, bodies and user state stay, and the feed adopts notices whose revision matches.
- **Studium:** a separate opt-in extension for manual or explicitly started app-open automatic checks of one to seven library reading rooms. Automatic mode is session-only and off at launch; its saved interval defaults to 5 minutes (integers 2–60). Selected rooms, the displayed room, room-specific favorites, default-off alert conditions and native mini-window geometry persist (schema 30). Exact-number search, favorite highlights and the optional relative seat map use the same validated response locally; map errors preserve verified numbers/counts. Fresh manual/automatic results may trigger opted-in seat alerts under the existing notification permission, quiet-hours and shared rate policy. The explicitly opened mini window and existing-tray summary share the same in-memory results; closing mini preserves any running check, and neither open state nor always-on-top survives a new window/session. Failed rooms lose their previous values; neither observed coordinates nor seat history are stored. Enabling, navigation, map operations and settings changes start no school requests or alerts. No reservations.
- **Meals (#318):** an opt-in 식단 page for the Bellarmine dormitory menu, which the collector reads by OCR from the menu image and publishes as `meal.week` (feed format 1.3). The app mirrors the weeks (migration 044), opens on today in Korea with Monday–Sunday tabs, shows the next week once published, and always links the original image; an unreadable or missing week never falls back to another one. Verification is in the table below.
- **Local AI:** upstream `llama-server` (llama.cpp b12068, bundled and supervised by Rhythm) on both platforms, running the one catalog model, Qwen3-Embedding 0.6B, for classification, similar notices and semantic search. Notices from the signed feed (#177) take the collector's categories and vectors and need no local model; the local model classifies only Cybercampus notices and embeds search queries; a v1 public notice the feed never described keeps the local rows it already had. AI summaries, vision projectors and the OpenAI-compatible remote engine were retired (#226, schema 33): their results were deleted, the saved remote API key is removed from the OS credential store on upgrade, and installed summary models stay listed only for removal.
- **Personalization, lifecycle and notifications:** deterministic ranking, opt-in background sync and notifications, backup and restore.
- **Calendar:** opt-in month view of open eClass deadlines, dates found in saved notices' text (plus every notice's deadlines behind a default-off toggle) and local todos (never sent anywhere) with optional native reminders while Rhythm is open (#189); todos not done and open eClass deadlines can be saved as an `.ics` file on explicit request (#191); unfinished todos and the same notice dates also show in 앞으로 7일. The school's academic calendar (학사 일정, #319) arrives through the feed (format 1.2; the collector reads the school's published Outlook calendar, 65 events on 2026-11-25) and shows in the calendar and 앞으로 7일 behind a default-on toggle. A found date or an eClass deadline can be copied into a todo through an editable, explicitly saved form; a todo from a notice links back to it. Date extraction is deterministic and Korean-only (#226): on one copied archive (1,081 notices, under 30 ms in a release build) and a second copy of 1,073 notices (2026-11-15): 532 notices have a deadline, 195 date rows have no label, 352 ranges became single spans, and the 32 deadlines the extractor drops were checked by reading (mostly residence, training and work periods). A random sample of 30 had the main date right in 26 of 26 Korean notices with dates and missed the one English date. English phrasing is not handled and image-only notices have no text to read.
- **First-run setup:** a new profile opens a guided setup (theme, boards, Cybercampus, interests, classification model, background, notifications) before the app; it can be rerun from Settings and resets nothing.
- **Windows 11 x64:** per-user unsigned NSIS installer, the CPU build of the embedding server, WinRT notifications. See [Windows](WINDOWS.md). v2 evidence (one PC, fresh profile, 2026-11-20): [Windows validation #271](WINDOWS_VALIDATION.md#v2-feed-cpu-classifier-and-release-build-271); upgrading a populated v1 profile on Windows and an installed-app v2 run remain unverified.
- **Distribution:** ad-hoc-signed macOS DMG and unsigned Windows installer, with signed in-app updates and a daily automatic update check (announce-only), built by the tag-triggered `release.yml` into a draft release.
