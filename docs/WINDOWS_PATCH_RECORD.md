# Rhythm Windows 호환 패치 종료 기록

기록일: 2026-11-02 (한국 시간)

사용자 요청으로 Windows 호환 패치 작업을 현재 상태에서 종료했다. 추가 구현·빌드·설치·시험은 진행하지 않는다. 이는 전체 계획의 완료나 정식 배포 승인을 뜻하지 않는다. 아래에는 구현한 내용과 실제 검증한 범위를 구분해 기록한다.

## 1. 원본과 보관 상태

- 원본 저장소: https://github.com/Hiyabye/Rhythm
- 기준 커밋: `476b22e132e40f02c8c2cdcb22cd79cc19d62d00`
- 작업 브랜치: `windows-port`
- 현재 소스: `D:\Codex_Rhythm\Rhythm`
- 종료 기록 작성 직전 변경 목록은 기존 추적 파일 64개와 새 파일 24개, 총 88개였다. 삭제 파일도 포함한 수치이며, 이 종료 기록은 별도로 추가했다.
- 패치 종료 기록 당시 변경 사항은 작업 폴더에만 있었으며 새 Git 커밋이나 원격 업로드는 없었다. 이후 사용자가 별도로 PR 작성을 요청해, 종료 시점의 변경을 커밋하고 포크에서 원본 저장소로 초안 PR을 제출하는 절차를 진행했다. 원본 Git 이력은 유지한다.
- Windows 11 x64, CPU 추론, 사용자별 NSIS 설치, 수동 갱신을 대상으로 했다. Mac 데이터 이전·GPU 가속·앱 내 자동 업데이트는 제외했다.

## 4. 실제 AI 시험과 제한

- Qwen3.5 2B와 4B를 실제 다운로드하고 전체 파일 SHA-256을 검증했다.
- 두 모델로 CPU 추론을 실행했다. 취소·워커 종료·재시작·결과 캐시 재사용을 검사했다.
- 2B 실제 다운로드 취소와 HTTP 206 이어받기 후 해시 일치를 확인했다.
- 격리된 워커에 메모리 제한을 적용해 할당 실패와 재시작을 확인했다. PC 전체의 메모리 부족 시험은 아니다.
- 2B는 시험용 장학 공지를 학사로 분류해 품질 검사에 실패했다. 실제 공지 요약에서도 날짜의 조건을 누락했다.
- 4B는 시험용 사례의 품질 검사를 통과했지만, 실제 공지에서 마감일의 정규화된 날짜가 비어 있었다. 일반 정확도 통과로 해석하지 않는다.
- 수집 공지 한 건의 시험 시간은 2B 약 75초, 4B 약 158초였다. 해당 추론 후 워커 메모리는 약 4.1 GiB와 8.3 GiB였다. 다른 동시 작업과 사례의 영향을 받으므로 보장 성능이 아니다.
- 설치본에서도 외부 2B 모델 등록·설정·분석 취소·분석 완료를 확인했다.

세부 조건·측정값·실패 사례: `WINDOWS_AI_RESULTS.md`.

## 5. 마지막 오류 수정과 미완료 빌드

첨부파일의 ‘저장 폴더에서 보기’를 누르면 탐색기에서 위치를 찾지 못하는 오류가 있었다. 실행 중인 앱의 데이터베이스 핸들을 확인한 결과 실제 파일이 Codex 패키지의 `LocalCache` 아래에 있었고, 탐색기에 전달한 일반 LocalAppData 경로와 달랐다. 앱에 패키지 ID가 없다는 사실만으로 이 경로 차이를 배제할 수 없었다.

소스에는 실제 파일 경로 확인, 자료 루트 포함 여부 재검사, 짧은 Windows 확장 경로 표기의 Shell용 정규화를 반영했다. 관련 검사 3개와 코드 검사는 통과했다. 그러나 수정된 설치본의 실제 탐색기 표시 결과는 미검증이다.

종료 시 `installer-physical-path-build.txt`는 Rust 컴파일 시작 이후 완료 기록이 없었다. 조회 가능한 cargo/rustc/makensis 프로세스도 없었으며, 설치 파일은 이전 산출물과 같은 해시였다. 따라서 마지막 수정본의 설치 파일 생성 성공을 기록하지 않는다. 종료 요청 후 재빌드는 시작하지 않았다.

Codex 실행 계보에서 관찰한 파일 경로 차이 때문에, 설치·레지스트리·바로가기 및 데이터 검증을 일반 사용자 실행 환경의 동일한 동작으로 확대 해석하지 않는다. 일반 Explorer 실행과 별도 환경 검증은 남아 있다.

## 6. 종료 시 남은 항목

- 마지막 첨부파일 경로 수정본 빌드 및 실제 탐색기 표시 재시험.
- 실제 로그인 후 자동 시작, 절전 복귀 후 예약 수집, 설치본의 예약 수집 동작.
- 알림의 실제 표시 및 실행 중·숨김·완전 종료 상태에서 클릭 이동. 사용자가 시험을 추후로 미뤘다.
- 트레이 열기·종료는 사용자 성공 보고가 있지만 당시 독립 프로세스 관찰과 차이가 있어 정확한 종료 경로를 확정하지 않았다.
- 최종 제거·재설치와 데이터·모델 보존, 전용 링크·자동 시작 등록 정리 확인.
- 복원 후 모델 및 만료 알림 정보 정리 등 설치본의 추가 경계 조건.
- 화면 배율·한글 입력기·접근성, 긴 경로·권한·공간 부족 등 남은 경계 조건.
- 개발 도구 없는 두 번째 Windows 11 x64 PC/VM 시험. 사용자가 별도 환경이 없다고 답해 미검증으로 남긴다.
- 모든 하드웨어의 갑작스러운 전원 손실 내구성은 보장하지 않는다.

## 8. 후속 PR 제출 범위

사용자가 패치 종료 후 별도로 PR 제출을 요청했다. 제출 대상은 종료 시점의 Windows 전용 변경이며, 미완료 기능을 완료로 표시하거나 새 설치 파일을 배포하는 작업이 아니다.

원본 `main`은 PR 준비 시 `de1a5fa71bdf06d114bea93f5c2e0b2d613ae6ac`으로 이동해 있었다. 기준 `476b22e` 이후 1.0.0 릴리스, AI 결과 안내 및 ZIP 의존성 보안 수정 등이 추가되었다. 현재 Windows 패치는 이 최신 원본과 아직 통합하지 않았으므로 병합 전에 충돌 해결, 최신 보안 수정 반영 확인 및 재검증이 필요하다. 기존 시험 수치를 최신 원본에 대한 검증으로 해석하지 않는다. 초안 PR은 검토를 위한 제출이며 병합이나 정식 배포 완료를 의미하지 않는다.
