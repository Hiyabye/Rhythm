# rhythm-sources (notice sources)

Area instructions for `crates/sources/` (catalog, parsers, transport, TLS). The root `AGENTS.md` (project-wide rules) applies too.

- `crates/sources/` (`rhythm-sources`): notice sources and their transport, shared by the app and the collector (#166); no storage, filesystem or Tauri. `catalog.rs` (173 sources, groups, the Cybercampus IDs), source-side record types (`model.rs`: `SourceDefinition`, `SourceGroup`, `ArticleInput`, `ResourceInput`, `ListingEntry`, `ListingPage`), independent native parsers (`parser.rs` plus `admission.rs`, `engineering.rs`, `community.rs`, `k2web.rs`, `mechanical.rs`, `semiconductor.rs`, `vendor.rs` and `wordpress.rs`) with the sanitizer, the URL/address policy for automatic fetches (`policy.rs`: `validate_url`, the embedded-image host rule, `public_ip`), PDF text (`pdf.rs`), notice date extraction (`dates.rs`), the constrained HTTPS transport (`transport.rs`: `Client`, `Access`, `validate`, the `Transport` trait; scripted client tests in `transport/client_tests.rs`), the Sogang chain completion (`tls.rs`, certificates and provenance in `certificates/`) and the robots policy (`robots.rs`). The `studium` Cargo feature adds `Access::Studium`, its exact-route validator and room IDs (`studium.rs`, which must match the app's `studium/rooms.rs`) and the pinned R46 root; it alone enables reqwest's `native-tls`, and only the app enables it, so the collector stays Rustls-only. `Client::new` takes the user agent (the app's is built in `archive::client`). `lib.rs::selector` caches parsed CSS selectors for all parsers (also Cybercampus). `src/fixtures/` holds the parser fixtures (provenance in its `README.md`); app tests include them by relative path, and `dates/tests.rs` reads `src-tauri/src/intelligence/evaluation.json`. The app re-exports the modules as `crate::archive::{catalog, dates, parser, pdf, selector, tls}`, `archive::network` (= `transport`) and `archive::sync::robots`, and `archive::model` re-exports the types.

## Catalog and parser rules

- Approved Sogang exception (main-site boards, `parser::main_board`): for a new notice whose fetched body consists only of one or more iframes, archive its notice metadata only while preserving the original fetched representation; leave sanitized body/content fields empty and record an explicit unsupported-body state. Never fetch or render the iframe or its content. If an existing notice has last-good readable content, an iframe-only/unsupported-body result must not replace it; that notice counts as checked, not as a failure or skip. PDF-viewer exception (user decision): an iframe-only body showing `scc.sogang.ac.kr/pdfviewer/web/viewer.html?file=<scc /Download3 PDF>` records that PDF as an attachment; once downloaded, its `pdf-extract` text (`crates/sources/src/pdf.rs`) becomes the body through `archive/sync/pdf.rs`, filled into the latest revision in place (no new revision/notice/freshness) when an opened feed notice downloads it or an explicit retry of that PDF succeeds; a v1 notice whose PDF was never downloaded gets the file on open but not the text (user decision, #178). Never fetch the viewer page. Scanned PDFs stay metadata-only with the PDF attached. Poster exception (user decision, 2026-11-24): a k2web notice whose body is only inline `data:` images and which has no attachment is archived metadata-only the same way (`parser::metadata_only_allowed` lists the boards allowed an unsupported body). `scc.sogang.ac.kr`'s robots.txt is unrendered ASP source: for that host only, `<% … %>` blocks are stripped and every branch's rules apply. `klec.sogang.ac.kr` has no robots.txt (HTTP 404): for that host only a 404/410 robots.txt means no rules (`transport::ABSENT_ROBOTS_HOSTS`); every other school host's robots error stays an error. `admission.sogang.ac.kr` answers robots.txt with its HTML not-found page (200 `text/html`): for that host only that page means no rules (`robots.rs`, user decision); every other host's HTML robots answer is refused.
- Catalog has 173 sources, all supported: the authenticated `cybercampus` connector (`src-tauri/src/archive/cybercampus/AGENTS.md`) and 172 public boards: the six main-site boards `sogang-academic`/`sogang-general`/`sogang-scholarship`/`sogang-events`/`sogang-student`/`sogang-onestop` (one BbsData JSON API; each board's `bbsConfigFk` and canonical-link query are in `parser::MAIN_BOARDS`; the site lists no page for `sogang-onestop` (종합봉사실, board 3), so its link is only `https://www.sogang.ac.kr/ko/detail/<pkId>?bbsConfigFk=3` (user decision 2026-11-24, #315), and attachments are allowed only under those boards' `/file-fe-prd/board/<id>/`; 보도자료 (104) is left out because its list marks every row pinned, #80), five `computing-*`, `eng-general`/`eng-careers`/`eng-academic`/`eng-research`, the nine `ee-*`/`sse-*` community boards, the 131 k2web boards (the three `dorm-*` dormitory boards and 128 college, department, graduate-school, office and institute boards, #80 step 3), the seven `me-*` mechanical boards, the five `se-*` semiconductor boards, `creative-news` (아트&테크놀로지학과, WordPress; #80 step 4), the three vendor boards `scec-notice` (미래교육원) and `klec-notice`/`klec-news` (한국어교육원; #80 step 4) and `admission-notice` (입학처 공지사항, every admission category as one board; #80 step 4). Engineering uses current `/board/{notice,recruit,academic,research}` SSR routes, not retired CMS routes (the e뉴스레터 gallery `/board/newsletter` is not a source); `parser.rs` dispatches to its source-specific `engineering.rs` submodule. The community family (`community.rs`) covers two aseoul board skins: `ee-news`/`sse-news` render galleries (12/9 rows), the other boards render 10-row tables whose pins occupy leading slots across pages 1-2, and both use `?m=v&idx=` details with `pNo` as the return page. The engine prints some titles unescaped (`<HD현대삼호 …>`), so the parser escapes a `<` whose tag name holds a non-ASCII character before parsing; the stored original stays as fetched (#258). The k2web family (`k2web.rs`, #80) covers boards of the school's k2web CMS: each board is one row of `parser::K2WEB_BOARDS` in `k2web/boards.rs` (source ID `<site>-<board>`, display name, page title the parser checks, organization `서강대학교 · <unit>`, group, site, menu, bbs, regular rows per page, table or gallery skin), which also builds its catalog entry and the policy's `new-cms.sogang.ac.kr` routes, so adding a board is adding a row (plus fixtures for an unobserved variant). The rows come from the 2026-11-23 census of the active boards; a board seen with only one page takes another board of its site's page size, else 10 (a wrong size fails the pager check once the board grows). 벨라르미노 학사 시설 관련 (menu 3945) is left out (user decision). Groups (`catalog::groups`, #80 step 3, user decision): under 서강대학교, the categories 단과대학 (departments under their college; 공과대학 and 소프트웨어융합대학 sit here), 대학원, 행정·지원 (with 벨라르미노 학사) and 연구소, then one group per unit even with one board; group IDs stay stable when a group moves, so its switch survives. Fixture tests run against the catalogued rows. Every request goes to `new-cms.sogang.ac.kr` (user decision, #80): lists `/<site>/<menu>/subview.do?page=N` whose pins repeat on every page (and may also appear as regular rows), details `/bbs/<site>/<bbs>/<article>/artclView.do` bound by the list form, `og:url` (or its literal `?`) and the hidden title (the shown title may carry a `[분류] ` prefix), attachments `/bbs/<site>/<bbs>/<file>/download.do`. A link post, like a private post (no link, `비공개된 게시물입니다.`), keeps its ordinal but is not archived; a login-only post (`접근 권한이 없습니다.`) is a permanent failure, so the collector records it as skipped (user decision, #80). Beyond the last public page the site still serves a pins-only page, so the declared total bounds paging. The calendar menu (6558) is a month-grid schedule with title/time-only entries and no article body or publication date; do not add it as a notice source or fabricate document fields for it. A future calendar view needs a separate event model. The host's inline editor images under `/CrossEditor/` and raster images under a catalogued board's own `/sites/<site>/` folder (user decision, #80) are approved; article images on `scc.sogang.ac.kr` are HTTP (and HTTPS 404) and stay unsupported references (that host's only approved route is the main board's PDF-viewer `/Download3` file). `robots.txt` on both hosts disallows `/se2/` and `/data/`, and on sse also `/bbs/`; the network policy approves only article routes plus ee `/aseoul_bbs/down.php`, so blocked images and sse attachments stay visible as unsupported and are never requested. The mechanical family (`mechanical.rs`) discovers articles through the public `/sitemap.xml`, because the site pages only as `?page=N` and its robots.txt forbids every query string (`Disallow: /*?`); the legacy `/bbs/board.php` routes answer a 429 challenge. The semiconductor family (`semiconductor.rs`) uses the current `board_list.php?board_id=<board>&page=<n>` and `board_view.php?board_id=<board>&no=<id>` routes, binds the pager and descending ordinals, downloads `/board/filedown.php` attachments and `/smart_editor/upload/` editor images, and records images from other school boards as unsupported. The sitemap listing filters exact `/ko/board/<board>/<id>` URLs, rejects duplicates/foreign hosts/query forms, sorts newest `lastmod` first, and reports one complete page (`has_next=false`). Each entry keeps `lastmod`; the collector skips an existing notice while its stored change time equals it, otherwise it refetches with validators. A missing or malformed timestamp always forces a fetch. Details are bound by `link[rel=canonical]`, the board label, author/date metadata and `div.prose-sg`; direct child image/video blocks are kept (iframes dropped). Attachments (Supabase or a legacy R2 bucket) are recorded from `첨부파일` but never downloaded from a third-party host. The WordPress family (`wordpress.rs`) reads a site's public REST API, never its theme pages or RSS: `parser::WORDPRESS_BOARDS` maps each board to one category; the list is `/wp-json/wp/v2/posts?categories=<c>&orderby=date&order=desc&per_page=50&page=<n>&_fields=id,modified_gmt&_envelope=` (`_envelope` carries the page count in the body; a page past the end is an empty last page, since deleted posts can shrink the count below a history checkpoint), a post is `/wp-json/wp/v2/posts/<id>?_fields=…` (published `post` in the board's category, not password-protected), the canonical URL is the stable short link `https://<host>/?p=<id>` (the app rebuilds the post route from it on open), `modified_gmt` is the listing's change time (RFC 3339 UTC, unchanged posts are skipped like sitemap entries, and the listing carries no title so a body-only edit is never skipped), `published_at` is the site's local `date`, and only raster images under `/wp-content/uploads/<yyyy>/<mm>/` are fetched. The policy binds every query key to the exact value the parser sends. A JSON family is listed in `parser::json_documents`, which both MIME checks use. Working list extraction alone is not support. Require verified full article/resource extraction and fixtures before changing support flags.

- `crates/sources/src/tls.rs` supplements only the exact `www.sogang.ac.kr`, `new-cms.sogang.ac.kr`, `eclass.sogang.ac.kr`, `scec.sogang.ac.kr`, `klec.sogang.ac.kr` and `admission.sogang.ac.kr` intermediate chains (the same Sectigo OV R36 intermediate). Intermediates are **untrusted candidates**, not roots. Preserve Mozilla roots and normal WebPKI hostname/validity/signature/usage/path checks. Read `crates/sources/src/certificates/README.md` before certificate changes; never repair connectivity by accepting invalid certificates or promoting intermediates to roots.
