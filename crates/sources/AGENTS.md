# rhythm-sources (notice sources)

Area instructions for `crates/sources/` (catalog, parsers, transport, TLS). The root `AGENTS.md` (project-wide rules) applies too.

- `crates/sources/` (`rhythm-sources`): notice sources and their transport, shared by the app and the collector (#166); no storage, filesystem or Tauri. `catalog.rs` (173 sources, groups, the Cybercampus IDs), source-side record types (`model.rs`: `SourceDefinition`, `SourceGroup`, `ArticleInput`, `ResourceInput`, `ListingEntry`, `ListingPage`), independent native parsers (`parser.rs` plus `admission.rs`, `engineering.rs`, `community.rs`, `k2web.rs`, `mechanical.rs`, `semiconductor.rs`, `vendor.rs` and `wordpress.rs`) with the sanitizer, the URL/address policy for automatic fetches (`policy.rs`: `validate_url`, the embedded-image host rule, `public_ip`), PDF text (`pdf.rs`), notice date extraction (`dates.rs`), the constrained HTTPS transport (`transport.rs`: `Client`, `Access`, `validate`, the `Transport` trait; scripted client tests in `transport/client_tests.rs`), the Sogang chain completion (`tls.rs`, certificates and provenance in `certificates/`) and the robots policy (`robots.rs`), and the academic calendar (`calendar.rs`: the published ICS URL, its exact-URL validator for `Access::Calendar` and the iCalendar parser, used only by the collector, #319). The `studium` Cargo feature adds `Access::Studium`, its exact-route validator and room IDs (`studium.rs`, which must match the app's `studium/rooms.rs`) and the pinned R46 root; it alone enables reqwest's `native-tls`, and only the app enables it, so the collector stays Rustls-only. `Client::new` takes the user agent (the app's is built in `archive::client`). `lib.rs::selector` caches parsed CSS selectors for all parsers (also Cybercampus). `src/fixtures/` holds the parser fixtures (provenance in its `README.md`); app tests include them by relative path, and `dates/tests.rs` reads `src-tauri/src/intelligence/evaluation.json`. The app re-exports the modules as `crate::archive::{catalog, dates, parser, pdf, selector, tls}`, `archive::network` (= `transport`) and `archive::sync::robots`, and `archive::model` re-exports the types.

## Catalog and parser rules

The catalog, per-family parser contracts, routes and host robots exceptions live in `docs/ARCHITECTURE.md` "Sources and parsers"; read it before changing a source or parser and update it with the code. Rules:

- Never fetch or render an iframe or the scc PDF-viewer page. An iframe-only or other unsupported body never replaces last-good content; that notice counts as checked, not as a failure or skip. Only boards in `parser::metadata_only_allowed` may archive a metadata-only notice.
- Never add the k2web calendar menu (6558) or another schedule grid as a notice source, and never fabricate document fields; a calendar view needs a separate event model.
- Never download third-party attachments, and never request robots-disallowed routes. A robots exception applies only to its named host; do not widen `transport::ABSENT_ROBOTS_HOSTS`, the scc/admission handling in `robots.rs` or the calendar host's reading under `Access::Calendar` to other hosts or accesses.
- Working list extraction alone is not support. Require verified full article/resource extraction and fixtures before changing support flags.
- Adding a k2web board is a row in `k2web/boards.rs` (`parser::K2WEB_BOARDS`), plus fixtures when it shows an unobserved skin or detail variant.
- A new JSON family must be listed in `parser::json_documents`, which both MIME checks use. The policy binds every query key to the exact value the parser sends; keep `policy.rs` and the parser's URL builders in step.

- `crates/sources/src/tls.rs` supplements the intermediate chain (the Sectigo OV R36 intermediate) only for the exact hosts in `tls::COMPLETED_HOSTS` (see `docs/ARCHITECTURE.md` "TLS chain completion"). Intermediates are **untrusted candidates**, not roots. Preserve Mozilla roots and normal WebPKI hostname/validity/signature/usage/path checks. Read `crates/sources/src/certificates/README.md` before certificate changes; never repair connectivity by accepting invalid certificates or promoting intermediates to roots.
