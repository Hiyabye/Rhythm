# Intelligence (embedding model and classification)

Area instructions for `crates/core/src/intelligence/`, `src-tauri/src/intelligence/commands.rs`, `crates/core/src/storage/intelligence*.rs`, `AiSettings.svelte` and `crates/embed`. The root `AGENTS.md` (project-wide rules) applies too.

- `crates/core/src/intelligence/` (crate `rhythm-core`, re-exported in the app as `crate::intelligence`): `Worker` (`mod.rs`) and its embedding `llama-server` supervisor `server.rs`, `models/` (`catalog`, `hardware`, `transport`, `download`, `gguf`) with the pinned `catalog.json`, `model_storage.rs`, the `classification.rs` embedding controller/loop (its only `Worker` user; the inputs, prototypes and scoring come from `crates/embed`); the Tauri commands stay in `src-tauri/src/intelligence/commands.rs`. The loop and `query_vector` take the store, `models::Controller` and data root explicitly; never pass app or UI state into core. AI summaries, the remote engine, backlog analysis and model registration were retired (#226). Test-only synthetic fixtures are `evaluation.json` loaded by `evaluation.rs` (also read by `crates/sources/src/dates/tests.rs`); the opt-in embedding evaluations are `embedding_evaluation.rs`. Collection never waits for AI.

## Process and engine

`intelligence::tests::real_server_lifecycle_without_model_weights` runs the staged real `llama-server` (or `RHYTHM_LLAMA_TEST_DIR`) and returns early when neither exists; a passing suite alone does not establish process integration. Other process tests use the fake `llama-server` in `crates/core/src/intelligence/test_worker.rs` (same flags, log lines, socket/loopback listener, API-key check and embedding response shapes): compiled once per test process from fixed source, with first launch completed before any request deadline, then hard-linked per test with its `mode` and control files beside it. macOS holds each newly created executable before its first instruction for an execution-policy check; per-test unique binaries launched in parallel exceeded the 8-second status deadline. Pass per-test behavior through files beside a hard link, never by baking paths into source. Do not raise request deadlines to hide launch latency. Actual-model embedding runs only in the ignored evaluations in `embedding_evaluation.rs`; never claim it verified without real output.

**Inference engine:** Rhythm supervises upstream `llama-server` as an embedding server only, pinned to one llama.cpp build number with per-archive size/SHA-256 in `scripts/llama-cpp.json` (macOS arm64 Metal; Windows CPU). Change the build and all checksums together, then rerun the real-model checks. Process flags, the socket/loopback key, timeouts and bounds, request reaping and orphan handling (`stop_orphan`, #273) are specified in `docs/ARCHITECTURE.md` "Inference process"; change that section together with `server.rs`. Never reuse a server after an abandoned request, and never let it listen anywhere but the private socket or keyed loopback.

**GPU selection:** macOS tries Metal and falls back to CPU (`-ngl 0 --device none`) for the session after a load or request failure. Windows runs only the CPU build (user decision, #178: the Vulkan build, the execution-mode setting and NVIDIA detection were removed); the schema-8 `ai_preferences.execution_mode` column stays, unread and unwritten. Do not download weights implicitly. Accuracy and platform evidence: `docs/AI_EVALUATION.md` and `docs/WINDOWS_VALIDATION.md`; do not claim beyond them.

## Verification and invariants

Focused deterministic checks:

```sh
cargo test --locked -p rhythm-core storage::intelligence_tests
cargo test --locked -p rhythm-core intelligence::classification
cargo test --locked -p rhythm-core intelligence::models
cargo test --locked -p rhythm-core intelligence::model_storage
cargo test --locked -p rhythm-core intelligence::tests
cargo test --locked -p rhythm-core intelligence::server
cargo test --locked -p rhythm-core storage::personalization_tests
cargo test --locked -p rhythm-core ranking_candidate_retrieval_is_bounded -- --nocapture
```

Normal tests must not download weights. The explicitly ignored `real_curated_model_install` exercises the production downloader with a pinned catalog entry only for validation. With approved weight/disk budget, set `RHYTHM_MODEL_INSTALL_ID` and `RHYTHM_MODEL_INSTALL_DIR` to a dedicated test directory. Never target production app data. The ignored `real_curated_model_cancel_resume` downloads the pinned GGUF into `RHYTHM_MODEL_RESUME_DIR` (a new isolated directory) and needs the same approval. The ignored `actual_embedding_classification_evaluation` and `actual_semantic_search_evaluation` take `RHYTHM_EMBEDDING_EVAL_MODEL` (with the staged build or `RHYTHM_LLAMA_TEST_DIR`, e.g. a bundle's `Contents/Resources/llama`); details and bounds are in `docs/AI_EVALUATION.md`.

- Catalog entries are pinned immutable repository revisions/files/size/SHA-256, not arbitrary URLs; the catalog pins only the Qwen3-Embedding 0.6B model (`kind: "embedding"`). Do not promote `experimental` to `verified` without real artifact/backend inference and useful-output evidence; catalog IDs allow only ASCII alphanumerics and `-`. Inventory rows whose catalog ID is absent (the retired generation models and their vision projectors, #226, plus the earlier `qwen35-9b`/`qwen35-0-8b`) must still open, remove and restore, and the UI lists them as no longer offered with only a remove action; never delete their bytes implicitly. A retired model's projector bytes are removed with the model; restore marks a projector `missing` unless its file is still present with the recorded identity under a still-installed model.
- Embedding classification is deterministic local similarity, not generation. A notice the feed described (`from_feed`) reads its vector and category only from `feed_embeddings`/`feed_classifications` (scope must name `storage::intelligence::FEED_MODEL`; any config hash, user decision 2026-11-20) and needs no installed model; every other notice uses the local model below, which embeds only Cybercampus notices (#178, user decision 2026-11-20): a v1 public notice the feed never described keeps the local rows it already has. Every AI read path joins through `classification_join`/`vector_join`. `intelligence/classification.rs` embeds an instruction + title + first 1000 body characters (`crates/embed`), compares the unit vector against authored Korean prototypes embedded with the same instruction prefix (the instruction keeps the original category list because stored vectors and search carry it), stores the raw score/margin and prototype config hash per revision, and maps a best score below `0.68` to `기타` with a low-confidence marker. The categories are 학사, 수업, 장학, 연구, 학과 소식, 공모전·대회, 인턴·채용, 교육·프로그램, 행사·활동, 생활·시설 and 기타 (user decision); adding one needs a migration that widens the `notice_classifications` CHECK. The raw score stays in SQLite. A model SHA-256 or config-hash change is a new scope; stored vectors allow reclassification without re-embedding. Latest-revision classifications (feed or local) also back the archive's **AI 분류** filter and counts and the **기회** page (`ArchiveQuery.opportunities`: four categories, nearest open `deadline` first, closed hidden unless asked; rules in `docs/ARCHITECTURE.md`); all display only, and unclassified notices never match. Stored vectors also back reader similar notices and list cross-post grouping (`Store::ai_similar_notices`): compare only latest-revision vectors (feed or local) within the newest `SIMILARITY_WINDOW` (2000) notices, and require an identical normalized title and identical body digit runs for a duplicate; grouping folds copies under an expandable row and never removes a notice. Semantic search (`archive_ranked_query`, #127) embeds the query locally with `SEARCH_INSTRUCTION`, only while classification is on with an installed local model that is not failed or paused after a failed embedding request (1, 5, then 15 minutes; `docs/ARCHITECTURE.md` "Inference process"), and fuses it by reciprocal rank with the text ranking; no model means text-only relevance ranking. Every text match must still appear exactly once across pages; the 0.20/0.08 cut-off was measured only on synthetic fixtures (`actual_semantic_search_evaluation`). Never feed classification into ranking, notifications, learned topics or network calls; vector similarity enters only the capped ranking term (Personalization invariants in the root `AGENTS.md`), never learned topics or network calls. Never delete archive content when removing the embedding model. The embedding artifact is a separate explicit install (catalog `kind: "embedding"`); classification runs automatically only after that install and can be switched off. macOS Metal was measured on 18 synthetic fixtures and 1,073 hand-labeled notices of a copied profile, the same notices the prototypes were tuned on (`docs/AI_EVALUATION.md`); Windows accuracy (one functional run, #271) and accuracy on other notices are unverified. The app sends no text to an AI service; only the collector sends public notice text, to Workers AI.
- Model transport is separate from archive transport. Keep HTTPS exact-host/path checks, public DNS/pinned answers, reviewed CDN redirects, disabled proxies and committed digest validation. Safe resume requires strong ETag and exact range validation; use generated `.part` paths and atomic finalization. Disk admission reserves 1 GiB beyond remaining weights.
- The embedding classifier is the only inference user: one transient process with its own `run/embedding` socket/key directory. It yields while a model download or exclusive maintenance is active and stops after a minute without work. Never abandon a request and reuse its server: stop/reap the process, then start a fresh one on demand. Inventory changes and the updater wait until the process is reaped (`stop_confirmed`/`stop_worker`).
- External GGUF registration (`ai_register`) was retired (#226); an existing external reference can still be unregistered. Preflight accepts GGUF v2/v3 `qwen3` (the embedding model) and the retired `qwen35`/`gemma4` metadata; it is not complete tensor/runtime validation. The classifier verifies the complete file once per model identity before first use; the approved `sha2` assembly feature applies only to macOS aarch64 and does not replace hashing with metadata or sampled bytes.
- Model-folder changes use only `ai_choose_model_directory`/`ai_reset_model_directory` and share AI/maintenance admission. `model_storage.rs` validates the native selection and resolves generated managed paths: on Windows it rejects links/junctions anywhere in the path, on macOS only a linked selected or `models` folder (system links such as `/var` are canonicalized). A new download captures its destination; existing models and interrupted downloads keep theirs. No implicit move/delete accompanies preference changes. A pre-existing final file in a chosen folder is adopted as managed only when that inventory already received every byte; otherwise installation is refused so removal can never delete bytes Rhythm did not write. Restore clears the preference and converts custom managed models to external/missing references without deleting their original files.
- Managed removal cleans ancillary partial bytes before weights, persists a conservative `missing` inventory state before irreversible unlink and reconciles failures. Do not restore selection to a noninstalled artifact. Unregister never deletes external bytes; model removal deletes that model's vectors and classifications and retains archived documents.
